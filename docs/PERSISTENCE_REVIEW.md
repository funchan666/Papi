# Papi 本地数据保存复核

2026-10-23。覆盖全部 30 个 Swift 源文件中读取、写入、清空、登录切换与金币变动的调用链。只做源码、配置、独立语法树与差异检查；没有读取设备 Keychain，没有运行 App、测试、编译、商品请求或支付。

## 本轮补强

| 部位 | 处理 |
| --- | --- |
| 原快照缺失 | 已成功保存或读取过快照后，在 Application Support 留下一个仅含存储服务名的存在标记，不复制账号、消息或余额。以后找不到 Keychain 原快照时进入不可写状态，避免把空数据当成新账号覆盖。标记跨进程保留，内存中也保留预期；首次从未保存过数据的安装仍可正常创建账号。 |
| 存储失败与重试 | 写入成功但读回验证失败时，保留“已有快照”的预期；重试读取失败继续不可写，不再直接恢复保存权限。账号切换或购买进行中不执行手动重载，避免替换正在处理的状态。 |
| 未完成购买恢复 | 启动/回前台之外，重新登录、存储恢复和账号操作结束也触发 unfinished 扫描。扫描进行中收到新恢复请求会合并为随后的一轮，避免直接丢弃重试请求；账号操作或存储不可用时不扫描交付。没有增加商品预加载，商品仍只在 Buy 时查询。 |
| 订单去重 | `CoinPurchaseTerms` 增加可选 `transactionID`，在交付快照中与余额、流水、已入账交易 ID 一起保存。已经绑定的订单 token 出现另一个交易 ID 时保留待处理，不再次加币。重复的同一交易仍走已入账分支，不增加余额。 |
| 历史订单 | 可选字段允许旧记录继续解码。旧订单没有交易 ID 时，仅在收到匹配 token/商品的已验证交易后补存关联；不按 SKU、当前页面或当前档位推断历史归属与数量。此前已 finish 且没有后续回调的记录不凭空补关联。 |
| 赠币与退款 | 首登原有协议版本/欢迎奖励判定之外，增加 `welcome-访客ID` 唯一流水判定。退款仍从原始入账流水取金额并与退款标记一起保存，补充整数减法溢出检查；不从当前商品数量重算旧订单。 |
| 举报记录 | 恢复隐藏集合和举报去重同时支持记录内的类型化目标与旧 `person:`/其他目标标识，避免旧记录重复写入或被遗漏。 |

## 已确认的现有保存行为（源码证据）

| 数据 | 保存、恢复与去重规则 |
| --- | --- |
| 聊天文字草稿 | 输入绑定直接写入 `letterDrafts`；没有等到页面退出或 App 进入后台才保存。切换页面不会主动清空。 |
| 聊天照片、语音草稿 | 照片导入完成、语音点击 Keep draft 后，引用写入快照；文件位于该访客的 Application Support 媒体目录，不依赖照片选择器的临时 URL。录音中的内容和未完成的导入不冒充已保存草稿。 |
| 消息 | 发送时校验互关、文案和附件，然后在一次 commit 中写入本地 outbox 并清除对应草稿；失败不发布新的状态，也不宣称送达。聊天没有金币扣减。 |
| 余额与流水 | 所有变动从同一个 `CoffeeHouse`/快照读取，成功写入且读回相同数据后才发布 UI 状态；没有从页面临时余额回写，也没有启动时根据当前商品档位重算余额。 |
| 购买 | 原始访客、订单 token、商品与金币数在购买前保存。已验证交易 ID、余额和流水一次落盘后才 finish。同一交易多渠道回调受 processing 集合和持久化交易 ID 保护；未验证、未知归属或未保存成功的订单不 finish。 |
| 首次欢迎 | 奖励、流水、欢迎标记与登录状态同一快照保存；重启可再次展示未确认的欢迎弹窗，但展示动作本身不加币。普通退出/再登录不重置这些字段。 |
| 消费 | 发帖扣币与私有待审核内容保存、草稿清空同一次 commit；配方扣币与已解锁集合保存同一次 commit，已有配方不再收费；收藏礼物扣币、库存和流水同一次 commit。上一轮已增加确认弹窗单次执行保护，没有添加页面出现时自动消费。 |
| 举报、拉黑 | 举报与隐藏集合同一次 commit；拉黑集合、关注/关系变更和已知用户资料同一次 commit。隐藏过滤只影响列表展示，不删除原聊天内容。解除拉黑只移除拉黑状态，已举报的内容仍隐藏，不自动恢复关注或好友。 |
| 普通退出登录 | 从完整 state 复制快照，只改登录/引导状态，保留同一访客身份、草稿、消息、余额、购买、报告和拉黑记录。重新登录复用这份快照。 |
| 删除账号 | 仍按明确确认后的原逻辑删除该账号的可用数据与媒体，保留购买归属与历史交易防重记录。它与普通退出登录的语义不同，没有将删除改成保留全部数据。 |

对照仓库旧版 `GuestState`/`GuestVault` 源码核对：原有 `CodingKeys`、Keychain service `Papi.LocalGuest.v1`、account `local-state` 和访客媒体路径均保留。新增订单关联为可选字段，没有为升级重建身份、清空余额或替换历史消费记录。单实例存储、禁用多 scene，以及按容器变化保持草稿/业务所有者的布局规则保留。

## 执行结果与限制

- `Scripts/inspect_project.py`：源文件入组、资源、多语言及 9 个商品配置等静态检查无发现，新增 3 条错误文案均有现有 5 个非英语语言翻译。
- 30 个 Swift 文件的独立 tree-sitter 语法树检查无未解决项；结果更新至 `SWIFT_SYNTAX_INSPECTION.json`。两处已知语法库识别限制仅在内存副本补空格，未改源表达式。
- `git diff --check` 通过。以上控制流按保存成功、写入前失败、写入后验证失败、重复回调、退出再登录等分支做了人工源码推演，未执行这些情景。
- 采用 Ponytail、Duo 的增量静态检查，并沿用 UI Design Reference、UI Taste、Impeccable 的错误恢复要求；没有重新设计布局或替换素材。

存在标记用于阻止静默覆盖，不是备份，无法找回实际已经丢失的 Keychain 快照。当前仍为本地版，无跨设备同步；卸载、设备迁移、介质故障和外部删除不在“普通重启后保留”的保证范围。未知订单继续保留待核对，不自动清空或转给新账号。

未执行 Swift 类型检查、编译、测试、杀进程/重启实测、锁屏与存储故障注入、Duo 设备验证、StoreKit 沙盒或真实支付验证。静态通过不代表这些运行场景已验收。

参考：[Apple Keychain 更新规则](https://developer.apple.com/documentation/security/updating-and-deleting-keychain-items)、[未完成交易](https://developer.apple.com/documentation/storekit/transaction/unfinished)、[appAccountToken](https://developer.apple.com/documentation/storekit/transaction/appaccounttoken)。每个新 token 仅结算一笔交易是 Papi 当前的订单约束，不是 Apple 对 token 的通用使用要求。
